# ForeSplat Fast Gaussian Cleaner：源码审查与代表样本研究

日期：2026-11-14。研究范围为原生 GGGS PLY 后处理，不重训、不改 Mesh、不启动19株批处理。外网博查实际返回 HTTP403（套餐/余额不足）；算法证据来自本地真实源码和实验。NumPy 2.5.4 文档通过 Context7 实际检索：<https://github.com/numpy/numpy/blob/v2.5.4/doc/neps/user/basics.rec.md>。这不是对黑云清理效果的文献背书。

## 1. 已有实现实际做了什么

以下路径均相对于清理器根目录；早期 V2/V3 在仓库根目录 `SuGaR-main/clean_3dgs_ply_v2.py` 和 `05-2DGS-new/clean_ply_v3.py`。本次未修改旧清理器。

令原始尺度 σ=exp(scale)、α=sigmoid(opacity)，DC 近似 RGB=C0·f_dc+0.5、b=mean(RGB)、c=max(RGB)−min(RGB)，C0=0.28209479177387814。**b 没有裁剪，不是实际完整 SH 颜色。**

| 旧规则 | 实际删除条件 | 成本与误判 |
|---|---|---|
| V2/C1 低透明度 | α<0.01 | O(N)，一个向量。GGGS filter 后 α 与原始 α 可相差很大；微小可见 Gaussian 的累计贡献不可由单点 α 认证 |
| 过大 | max(σ)>0.5 | O(N)，场景世界尺度不同，固定阈值不可通用；长叶/茎大轴可能正常 |
| 暗色 | b<0.10 | O(N)，会删暗叶、阴影、盆等；不含高阶 SH 的方向变化 |
| 暗且大 | b<0.20 且 max(σ)>0.05 | O(N)，仍用绝对场景单位 |
| 暗且低颜色范围 | b<0.25 且 c<0.06 | O(N)，灰黑盆与中性阴影可被误删 |
| 全局位置离群 | d=‖xyz−median(xyz)‖，d>mean(d)+3std(d) | O(N)，这是径向距离统计，不是局部统计离群；非球形冠层的叶尖可能被选中 |
| V3/C2 分档 | s>median(s)×{1,1.5,2.5} 且 b<{.15,.20,.28}，各档取并集 | O(N)，按全场中位数忽略局部叶/盆尺度差异；原 V3 仅两轴，native C2 已扩三轴 |
| V3/C2 KNN 暗色 | b<.35 候选，20邻居中位亮度 m，b<.4m | 树构建常见 O(N log N)，候选查询 O(C(log N+K))；树存双精度 XYZ 等 O(N)，原 V3 可一次持有 C×21 距离/ID/亮度。深叶与亮叶交界误判；均匀黑云相互支撑漏检 |

`cleaner/adaptive/legacy.py` 同时实现 faithful 与 normalized 版本；后者最大尺度阈值改为 Q.995，暗大尺度 Q.9；V3 用有效最大尺度/局部4邻居中位间距（场景中位间距作为下界），20邻居查询还限制半径=4×max(间距,有效中轴)、至少5个有效邻居。该函数即使 C1 也默认执行全量5近邻和暗候选65近邻、workers=8。纯规则本身没有额外磁盘 I/O，但入口包装会放大 I/O。

有效参数来自 `../gggs_community/scene/gaussian_model.py::get_scaling_with_3D_filter/_filtered_scaling_and_coef/get_opacity_with_3D_filter`：

σ_eff,i=hypot(exp(scale_i), filter_3D)

α_eff=sigmoid(opacity) ∏ᵢ σᵢ/σ_eff,i。

薄叶应与针状区分：max/min 的高比值不代表针状，历史代码使用 max/中轴>10；即便是真实针状茎，也不能仅凭该比值删除。

本地既有208相机、最大边960的对照见 `experiments/GGGS_Cleaner_Comparison/comparisons/C1_C2_GGGS_ADAPTATION.md`：C0 FG-PSNR20.0621、背景Alpha/FG面积0.863148；C1原阈值18.3104/0.039089；C2原阈值17.2837/0.035527；C1/C2相对版本分别18.0665/0.038264和17.5012/0.035741。删云与前景损伤存在明确权衡；不能把删除点数当质量分数。原KNN额外4446个候选承载0.491%前景贡献，仅0.0135%背景贡献，不能据此认证为安全废点。

## 2. R5 的收益与不可替代机制

真实源：`../experiments/KongQueZhuYu/gaussian_mesh_algorithm_selection/gaussian_mesh_artifact_refinement/scripts/{build_rounds.py,iterate_cleanup.py}`；记录见其 `task0_gaussian_cleaning/{CLEANING_ANALYSIS.md,diagnosis/GAUSSIAN_ARTIFACT_DIAGNOSIS.md}`。

R1：已有P2删除并上真实背景危害比 bg/(fg+bg)>.99 且bg>.05。R2：>.95，加背景主导（>.8）、低前景贡献、前景支持距离>.0069557324 或针状比>10且深度支持<2。R3对混合大Gaussian原σ×.5，但filter不变也改变有效透明度；收益不足没有选入最终R5。R4/R5对**当前剩余模型重新测量**8训练+8自由视角贡献，以max(原208平均FG,当前8平均FG)保护前景，再用ratio>.95、bg>.05删除；去前层才暴露的黑层是核心机制。

原模型黑权重50%分布于2558个ID、90%于15152个ID，不是几个极端尖刺。R5真实保留513840行，独立去3592个标记后的Best_PlantPot才是510248行；二者不能混称。历史固定8视角黑像素3478163→68393（R5）；Best68362。该指标含Alpha>.5、灰背景RGB亮度<.12、P3轮廓外>5px，属于像素总和而非物理面积。历史FG-PSNR条件原19.460452→R5 19.512784，与新960条件不能直接比；去标记版本18.680548。历史已记录盆沿变亮、局部深度变化与残留黑条。

可低成本借鉴：有效尺度、针/片区分、候选空间支撑、局部相对尺度、前景保护优先、失败如实记录。**不能从PLY认证**：T×α真实可见贡献、相机背景/前景归属、遮挡层重现、方向SH颜色、标记语义或盆叶归属。体素连续性只是保护代理，不能复制R5的渲染归因。

## 3. I/O 放大路径

`cleaner/io.py::read_ply`：PlyData.read默认mmap，再 `.data.copy()`；mmap页面实际访问仍要读盘，不能当无I/O。`save_ply`又复制完整数组再写。`sha`每次扫描全文件。`cleaner/adaptive/artifacts.py::export`写保留native+viewer、删除native+viewer，原生/删除合计两个全模型大小，再扫描native SHA，写ID。

`clean_legacy_gggs.py`在读取后扫描原文件SHA，export后扫描结果SHA，结束再次扫描原文件SHA，再保存deletion_reasons.npz。令输入S，保留比例r，native字段宽不变，PLY本体逻辑流量至少 **(5+2r)S**：输入及两次源哈希3S、两套互补输出2S、export及完成结果哈希2rS；不含NPZ和评价。r≈1时7S。若算GPU模型加载、parity/quality/visuals会更多。

`cleaner/historical/runner.py::_model`每个candidate：save_ply(Sᵣ)→scene.load_model（read_ply+model.load_ply两次）→sha(Sᵣ)，至少4Sᵣ。每个accepted同样至少4Sᵣ。每轮另有residual_discovery/foreground_damage/贡献NPZ、ID、行身份JSON。stage1、stage2和最终native/viewer/removed、重复SHA会继续叠加。

`cleaner/historical/evidence.py::measure`每点8个float64+4个int32，约80N字节，再加原FG、max_radius、辅助数据、per-view渲染与身份ID；千万点单轮贡献数组本体约800MB。遮挡重归因还需每轮更新。`cleaner/adaptive/runner.py`保存discovery/evidence.npz、best_so_far、quality_selected、最终多版本，候选优化/多视角评价重复加载和保存。读写量应区分静态估算与实际块设备计数，旧路线无进程级完整I/O测量，不能虚构实测倍数。

SH3、无SG原生行63 float32=252字节：1M约240.3MiB；10M约2.347GiB。按r≈1：旧C1/C2包装至少1.64/16.43GiB；新一次读写约0.469/4.694GiB（理论≈71.4%减少）；新低内存两次读写约0.704/7.041GiB（理论≈57.1%减少）。单个完整候选生命周期至少0.939/9.388GiB；10候选+1accepted仅此部分已约10.3/103.3GiB，尚不计渲染缓存。该表是数据传输公式估算，非旧路线实测。

## 4. 最终原型公式、资源结构与边界

实现：`fast_ply/{features,spatial,io,core}.py`，CPU入口 `fast_clean_gggs.py`。无torch导入、相机、Mask、外部几何、Renderer、LPIPS、训练；完整原始字段包含未知额外字段一并保留。仅支持native vertex-only binary little/big endian PLY；ASCII/list/非vertex元素显式拒绝，防止静默丢数据。

紧凑特征：XYZ、σ_eff最大/中轴/最小、α_eff、b，共32N字节。分块双精度计算filter公式，再存float32；原始记录字节不变。全局分位数用至多20万行确定性等间隔采样。D=b≤Q.05，L=s≥max(Q.995(s),3Q.5(s))，A=α_eff≤max(1e−5,.25Q.01(α_eff))；候选C=D∨L∨A。分位数不直接触发删除。

稀疏体素边长h=max(4Q.5(有效中轴),稳健Q.01–Q.99包围对角线/4096,全范围/(2²¹−4),float32最小正常数)。21bit×3精确无碰撞编码，保留边界空单元防串轴；np.unique排序后统计计数、亮度和、log尺度和。只对C分块搜索27邻居，排除自身，重复中心仍算实际支撑。得到邻居数u、邻域平均亮度bₙ、邻域几何平均最大尺度sₙ，26方向占据及13组相反方向。

局部异常：S=(u<3)，Dₗ=(b<bₙ−.02 且b<.5max(bₙ,.02))，Lₗ=(s>3sₙ)。删除提案：

[A∧(S∨L∨Lₗ)] ∨ [(D∨Dₗ)∧(L∨Lₗ)∧(S∨Dₗ)]。

最终保护：相反方向有占据且非Lₗ；或b≥Q.2且u≥3。该保护宁可留下相互支撑的黑云，也不把薄、细、暗作为单独删除依据；这是待测权衡，不能预先宣称解决黑云。

复杂度：特征O(N)、体素unique O(N log N)、候选查询O(27C log V)、原生复制/导出O(S)。没有全量KNN树、稠密矩阵、候选渲染或迭代文件。空间O(N+V+C+block)，主要数值工作集保守估算240N+块缓冲+96MiB；若再容纳原生S则一次读，否则保留紧凑特征和keep、第二次顺序读并直接输出；连紧凑空间都不足时明确MemoryError，不换页、不生成scratch文件。

限速器共享读写字节预算，256KiB传输前主动等待n/(20MiB/s)，不累计计算阶段的空闲额度。峰值统计为尾随1秒的**应用层逻辑**字节；`/proc/self/io`单列read_bytes/write_bytes反映缓存相关物理计数。不能据此保证共享设备全局峰值或内核readahead/writeback峰值；需要硬设备上限时由管理员配置cgroup v2 io.max。ionice不是带宽限制。fsync只在最终文件结束时执行。输出partial原子改名仅占最终文件自身空间，无额外完整副本。

报告包含完整读写次数/字节、CPU时间、墙钟时间、限速等待、每百万成本、峰值RSS、逻辑一秒窗口峰值与最大传输块、物理计数差、无中间数据文件。报告JSON自身的小量写入不计入PLY带宽统计。首次失败原型mmap绕限速的记录保留但已标记invalidated，不计入正式结果。

### 5.4 被拒绝的亮邻域/体积簇探针

基于“黑云互相提供支撑”的实测失败，另试候选b≤Q.2；可靠邻居为b>Q.2且alpha_eff≥Q.2(alpha_eff)。在候选27体素上，以26方向占据向量协方差特征值λ0≤λ1≤λ2估计体积性，λ0/max(λ1,1e−9)>.35，且可靠邻居<3，作为额外联合删除。它不是Gaussian真实协方差，也不能把方向栅格体积性当作真实生物结构分类。合成的独立暗平面/线、暗体积簇测试能分开，但真实模型不成立。

实际删除43,322，保留533,074。固定8黑像素3,478,163→3,213,804，下降7.6005%；FG-PSNR=20.34090，暗前景MSE=0.015034（较原增18.17%），边缘覆盖=0.902298，新空洞=0.041726%。删除数约为joint的66倍，仅多清掉约2.54个百分点黑像素，却增加暗前景误差与空洞。**拒绝该机制并从fast_ply/CLI中移除**。失败结果和可复核代码差异保留在 `reports/fast_ply_20261114/rejected_anchor_probe.patch` 与 `KongQueZhuYu_anchor_probe_quality.json`；不把这个探针推广到其他植物。

## 6. 方法选择与尚未解决的问题

本轮选择并交付的**工程架构**：CPU紧凑特征、候选查询、一次决定、显式限速顺序二进制I/O、自动内存路径、单一最终原生PLY。它不依赖全量KNN、相机、渲染贡献、额外点ID/ROI或训练。这部分由三株开发模型及一株留出资源实测支持。

**清理判定规则没有通过质量验收，不能称为最终已验证的通用算法。** 冻结joint仅作为可执行的保守研究原型保留，与attributes/appearance/isolation消融一起便于复核；不是建议用户批处理默认算法。没有足够证据用更复杂的空间模块替代更简单的appearance联合版本。没有将R5 ID作为输入、监督标签、阈值或特征，没有利用留出结果重调规则。

放弃：全量KNN（内存/计算与黑云自支撑问题，且旧KNN实测增量有前景贡献）、固定世界尺度、DC暗色或高各向异性单独删除、最大/最小比直接判针、全局距离外侧裁切、依赖手工ROI/ID、候选渲染优化循环、逐视角贡献缓存、每轮模型和默认viewer/removed双导出。额外体积性探针因真实暗前景损伤而移除；大数组/完整模型哈希和磁盘mmap彻底不在默认清理路径。

纯PLY局限不是“任何纯PLY方法都不可能成功”的证明。它只说明本轮测试的低成本规则未解决问题。一个Gaussian同时承担叶缘与背景、方向SH和遮挡层的可见性、相机/语义前景归属，不由DC和局部中心分布唯一决定。R5重归因仍有实测无法被当前几何近似替代的价值。后续若继续研究，应先改善可辨识特征和失败样本验证，而不是增加候选渲染或反复存盘掩盖问题。

## 7. 八项结论与交付状态

1. **相对C1/C2质量提升多少？** 孔雀竹芋同16观测视角FG-PSNR高2.1766/3.4108dB，但固定8去云仅5.06%，弱于C1/C2；不能宣称综合质量提升。其他植物没有已有同条件C1/C2结果，本轮未伪造跨植物基线优势。
2. **相对R5差距？** 同固定8黑像素3302202 vs68393，残余约48.3倍；R5前层删除后的重新归因能力、前景贡献包络与实际视角支持是主要差距。
3. **暗叶/细结构保护？** 孔雀竹芋薄结构代理不变但暗前景MSE上升；其他模型边缘/薄结构覆盖下降。没有足够证据认证暗叶/叶柄无损。
4. **实际总I/O下降？** 新清理实际逻辑量与物理计数均已报告；对旧wrapper只能按源码预测逻辑量降低约57–71%，没有同条件旧物理测量，不写成实测物理降幅。整个研究额外评价有单独I/O，不能计入一次读写清理成本。
5. **峰值受控？** 4株应用层尾随1秒均低于20MiB/s、单次块≤256KiB；物理设备峰值未测/不能由用户态硬保证。
6. **共享服务器资源？** 已测默认CPU清理约2.13–2.32 CPU秒/百万，9.17M紧凑路径RSS约992MiB，总356.34秒主要是333.05秒主动限速。工程开销达到本轮目标。评价独立使用GPU1，默认清理GPU占用为0。
7. **纯PLY仍解决不了什么？** 当前规则不能可靠消除相互支撑的密集黑云、附着黑条与混合前景/背景Gaussian；方向颜色、遮挡和真实语义缺失，Mesh几何连续性未获认证。深度与RAP骨架只是代理，未改Mesh方法。
