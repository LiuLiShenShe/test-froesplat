# GitHub 原版清理器实测计划

仅做第三方原始函数与原生 GGGS 记录之间的输入输出适配，不设计清理规则。

1. 固定 CorbeauSplat、3dgsconverter、splat-slim 的 commit，核对实际参数、激活定义、原始 ID 映射与依赖。预计 10–20 分钟。
2. 添加 external_cleaners/run.py：一次限速读入，CPU 原函数得到 ID，按原始二进制记录分块导出唯一最终 PLY；记录 CPU、墙钟、RSS、逻辑字节及应用层 1 秒峰值。默认 20 MiB/s、单任务串行，拒绝覆盖输入与已有结果。预计 15–25 分钟。
3. 孔雀竹芋分别执行 medium、官方 5/8、splat-slim 默认参数。核验保留记录及完整 filter_3D/SH/rotation 字节。预计每方案 1–5 分钟，以实测为准。
4. 给 fast_ply/evaluate.py 增加最终外部模型输入；16 观测视角、已有固定 8 自由视角、相同指标与 GPU1；历史 C2 和真实 round_05 R5 复用已有结果。保存同视角图。medium 大云残留才执行 strong。预计 10–20 分钟。
5. 根据实际渲染选择 1–2 个外部方法在长寿花1验证，参数不变，不启动其余植物。预计 5–15 分钟。
6. 汇总 sources.json、资源 JSON、图与决策报告。历史未测资源写“未测量”，不根据点数推断清理优劣。预计 5–10 分钟。

验证重点：上游源码未改、原始 ID 精确映射（尤其两阶段筛选）、输出记录字节不变、评价视角与历史一致。计算与 GPU 评价分阶段计量。内核写回不属于应用层速率的硬上限。
