# Native visual delivery execution

Status: prepared, not rendered. Current GPU execution belongs to the parent experiment queue. All exact command arrays and intended output locations are in visual_delivery_commands.json; none of the intended image locations is claimed to be an existing experimental output before execution.

E11 native shared freeviews use the original corrected E11 source at geometry_mesh_final_selection/camera_interface/2dgs_corrected and the actual30K native2scale PLY. Run scripts/render_e11_shared_free.py with /data/fj/F2DMAS/2d-gaussian-splatting-main/venv/bin/python through uv. Default is the original eight exact shared_free_views.json matrices. For the two additional inspection cameras, use --protocol comparison/shared_inspection_views.json and a separate --out. Image folders contain actual native RGB/Alpha, median and expected depth, raw alpha-weighted world normal plus correctly rotated camera normal, and exact camera metadata. Visual depth_ratio1 selects native median; the original E11 training configuration depth_ratio0 is separately recorded.

E14 surfel/refined visual wrappers accept the same optional --protocol and --out without changing original fixed-eight/shared-eight outputs. Refined3D Gaussian outputs retain native RGB/alpha; center-Z/axis-normal maps are explicitly AUX. Original native3D rasterization has no true surfaceDepth/Normal.

scripts/render_mesh_geometry_visuals.py accepts --mesh, --input, --out and --normal(world/camera), with optional --protocol for extra inspection poses. Without --mesh it renders every actual E14 Mesh stage. Each Mesh builds one BVH shared by all its8 cameras; camera K/W2C projections are recomputed, then the scene/Mesh/large arrays are released before the next file. With a208-camera input it only raycasts the fixed eight IDs0/26/53/79/105/131/157/183. Gray uses the identical two-sided headlight0.2+0.8*abs(camera_normal.z), background.25. World and camera-normal PNGs are both retained; normal.png follows --normal.

Wireframe comes from actual triangle-edge3D segments clipped at positive camera-Z, projected through the corrected K, and shown only for the frontmost ray-hit face at pixels within.65px of the edge. It does not run RGB, normal-map or silhouette edge detection. wireframe_mask.png and wireframe.png retain the actual geometry edge pattern. CPU validation showed an interior diagonal on a completely flat, constant-normal square. An actual OBJ/MTL/PNG write/read fixture additionally verified UV interpolation and V-axis orientation; the fixture is explicitly not an experimental model.

vertex_color.png is produced only if the actual Mesh carries vertex colors. textured.png is produced only from actual per-corner native OBJ UV coordinates and decoded referenced material images. P1/P2 tetra meshes without native color/texture are marked unavailable for those channels and never colored gray under a texture label. Actual texture materials are sampled separately from the tensor raycaster, which is used only for face visibility.

E14 run_all_e14.py adds independent07b actual Mesh visual delivery and09 actual native viewer HTTP smoke while leaving all original completion flags intact. Its final stage loads the actual E11 native2scale PLY and actual E14 refined3scale PLY in separate sequential native services. It stores HTTP RGB/alpha/depth/normal responses at yaw0 and180 about the shared worldY pivot. Refined depth/normal image names and metadata use AUX. Both process groups and HTTP listeners terminate before overall STATUS can become complete and the historical GPU queue starts.
