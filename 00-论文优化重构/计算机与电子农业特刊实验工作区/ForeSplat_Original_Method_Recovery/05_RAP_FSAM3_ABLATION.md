## 0. 结论先行（与上一版不同的地方已标注）

1. **完整 RAP-FSAM3（R6）在开发集上不是最优配置**：potted_plant F1 0.7517，而最简单的 R0（单提示词 P2 + base 排名）是 0.9828。四个场景中有三个 R6 显著低于 R0。
2. **主因是 SG-MPS 的提示词选择，不是 CDR / SB-FBPR / 残差修复 / GCFC。** 关掉门控（R3n）立刻回到 0.9763；打开门控（R3）掉到 0.7504。
3. **⚠ 更正：承诺裕度 0.05（R3g）能大幅缓解但不能"完全恢复"。** 上一版只看了 CaoMei1 / ChangShouHua2 两场景，结论是"回到无门控水平"。补齐 DouBanLv1 / XianKeLai1 后，R3g 整体 0.9435 < R3n 0.9763，DouBanLv1 从 0.9853 掉到 0.8803。逐帧核对后原因是**裕度只在近 ties 时让位**，而 DouBanLv1 0025/0050 两帧的 $c$ 差恰好 0.0567 / 0.0540，**超过 0.05 阈值**，门控"自信地"选了错误的 P1；裕度管不到这种情况。（CaoMei1 与 ChangShouHua2 的错选帧裕度都 <0.05，因此被让位抵消。）
4. **⚠ 更正：GCFC 在开发集上是"执行并被接受"的**，不是"未触发"。接受帧数 CaoMei1 2/5、ChangShouHua2 5/5、DouBanLv1 4/5、XianKeLai1 1/1；但其 F1 增量 ≤0.0002。被拒的 4 帧原因分别是 `support_gate`（3 帧）与 `no_corrective_delta`（1 帧）。
5. **SB-FBPR 是四个细化模块中唯一稳定为正的**，但量级很小（相对 R3：框提示 +0.0055 平均、点提示 +0.0012 平均），且点提示在 XianKeLai1 上 −0.0174。
6. **残差修复在本子集上增量为 0**（R5 与 R4p 逐帧完全一致）。
7. **CDR/R1 在本子集上增量也为 0**（R1 与 R0 逐帧完全一致），因为 R0 本身就已经选中了 oracle 实例（选择率 1.000）。

**判定：机制全部真实存在、真实执行、可观测；但"完整 RAP-FSAM3 优于单提示词基线"这一主张在本开发集上不成立。** 这是负面结果，必须写进论文，不得只报增益。

## 3. 换 GT 口径后结论翻转——这是本报告最重要的一张表

同一批掩膜，换成 `mask_plant`（只要绿色植株、不要花盆）与 `mask_pot`（只要盆）后重算：

| 档位 | F1 (potted_plant) | F1 (plant_only) | F1 (pot) |
|---|---|---|---|
| R0 单提示 P2 | **0.9828** | 0.7392 | **0.5256** |
| R3n 多提示无门控 | 0.9763 | 0.7450 | 0.5065 |
| R3g 门控 + 裕度 | 0.9435 | 0.7762 | 0.4350 |
| R2/R3 门控 | 0.7504 | **0.9516** | 0.0582 |
| R4b 框提示 | 0.7559 | 0.9553 | 0.0602 |
| R4p 点提示 | 0.7516 | **0.9576** | 0.0529 |
| R6 完整 RAP | 0.7517 | 0.9575 | 0.0530 |

**读法**：SG-MPS 并没有"选错"，它是在**按自己的语义定义正确地**选 `green plant`（P1）一类提示词——它优化的是"绿色植株"，而本实验的主口径 GT 是"带盆整株"。同一批掩膜在 plant_only 口径下 R6 = 0.9575，远高于 R0 的 0.7392。

由此得到两条互斥的、必须由论文作者决定的解释：

- **解释 A（目标定义不一致）**：论文 §2.3.2 明写目标是 potted-plant，但 $\phi$ 里的 $q_{plant}$ 代理（ExG 绿色占比 + 目标框重叠）与 $q_{table}/q_{neighbour}$ 惩罚项实际在优化"纯植株"。这是**目标函数与评测口径的定义冲突**，不是数值 bug。修法是让 $\phi$ 显式包含"花盆应被包含"的证据项（论文 §2.3.3 目前没有这一项）。
- **解释 B（门控不该存在）**：把 SG-MPS 降级为可选安全机制、默认关闭，主口径用单提示词 P2。

本恢复实验**不擅自选择**，两种情况都如实记录（见 §9）。

两种失败机制必须分开写进论文：

- **裕度让位后**，选择退回在**全部 5 个提示词的候选池**上做排名；此时排名自己也会偏爱 P1（ChangShouHua2 0025）。让位≠回到 P2。

### 7.1 最典型的单帧失效：KQZ 0008（全场景 run，有完整候选池证据）

这一帧的价值在于：**正确答案就在候选池里排第 0，门控把它排除了**。

| 项 | 值 | 来源 |
|---|---|---|
| SG-MPS 三个提示词的 $c$ | P1 0.3350 / P2 0.3319 / P3 0.3331（极差 **0.0031**） | `逐帧报告.csv` 的 `sg_mps_softmax` |
| 门控选择 | **P1** | 同上 |
| P1 内部排名第 1 的实例 | P1#8，面积比例 **0.0085**（低于 `--area_min_ratio 0.01`） | `候选评分明细_0008.csv` |
| **全局排名第 0 的候选** | **P2#2，面积比例 0.2253，SAM3 分数 0.957** | 同上 |
| 冻结 C_R1 基线掩膜前景占比 | 0.2266 | `metrics/mask_geometry_rap_vs_cr1.json` |
| RAP 最终掩膜前景占比 | **0.0086** | 同上 |
| SB-FBPR | 拒绝（`low_iou_guard`） | `逐帧报告.csv` |
| GCFC | 拒绝（`support_gate`，$G=0.0024$） | 同上 |
| 结果 | 一张**几乎为空**的掩膜进入下游 3D 训练 | `最终掩膜/mask_0008.png` |

三重保护（面积项、SB-FBPR 的 IoU 守卫、GCFC 的支撑门）**都没有拦住它**：面积项只把 $q_{area}$ 记为 0 而**不排除候选**；另外两个守卫只保护"细化/修正"环节，不检查最终产物的合理性。

这是 SG-MPS 近 tie 抛硬币的最坏后果，也是"下游指标为何变差"的直接单点证据。**修复需要作者决策**（给 $\phi$ 补目标一致性证据，或加终态面积守卫并接受它超出原稿定义），本恢复实验未擅自修改。

## 9. 诚实结论与待决问题

### 11.3 增益从哪里来（关键归因）

1. **不来自门控**：`R3n`（无门控）、`R3g`（裕度 0.05）、`R3gm05` 三种门控设置与单提示基线

   与基线同分，选错时（1 帧）才掉分。
2. **不来自 CDR**：R1s = R0s（逐帧一致），CDR/R1 在单提示模式下无作用。
3. **来自 SAM3 重提示（SB-FBPR）**：`S1s` 在**基底已经正确**（单 P2）的前提下，用

   证据一：`SB-FBPR提示证据.csv` 16/16 帧 `prompt_form=boxes`、`boxes_positive=1`、
   `boxes_negative=8`、`sb_fbpr_reason=ok`（对照 R1s 为 `module_off`）。
   证据二：gap-to-oracle = **−0.0022（负值）**，即 S1s 比"从候选池里挑最好"的上限还高，
   这在纯选择类方法里不可能出现，只能是重提示引入了候选池之外的新信息。
   证据三：逐像素看增益方向——`CaoMei1 0025` 新增 23 618 px 中 **91% 落在 GT 内**
   （F1 +0.0091）；失分帧 `ChangShouHua2 0075` 删掉 30 368 px 中 29 896 px 本是目标
   （F1 −0.0061），`DouBanLv1 0100` 新增 12 325 px 只有 32% 落在 GT 内（F1 −0.0024）。
   即重提示是"有时修对、有时修过"，净效果为正。
4. **细化必须建立在正确基底上**：`R4b`（多提示门控 + 框提示）只有 0.9797，低于 S1s 0.9860。

   **细化是乘性放大，不是无条件增益。**
5. **裕度 0.05 让多提示链路退化回单提示**：`R4bm05` / `R6m05` 与 `S1s` 数值几乎相同
   （oracle 率 1.0），因为裕度在近 tie 时让位后，16 帧全部落到 P2。这说明"多提示 + 门控"
   在本数据上的实际行为等于"单 P2 + 细化"，多出的 4 个提示词没有带来额外信息。
