# 开发约束与组合规则

本文件是后续所有算法模块开发的硬约束。任何 M1-M5 的实现都不能破坏这些规则。

## 1. 总约束 Prompt 固化

后续所有算法模块开发必须保持单分支、可开关、可组合的实验结构：

- 默认配置必须能够严格运行 baseline。
- 每个新增模块都必须提供独立开关。
- 每个新增模块必须支持在 baseline 基础上任意组合运行。
- 新增模块不得强制污染 baseline 路径。
- 新增模块不得破坏已有模块组合。
- 必须保证不同模块组合可以用同一套代码、同一套训练入口和明确的命令行参数完成消融实验。

示例组合：

```text
baseline
baseline+M2
baseline+M2+M3
baseline+M4
baseline+M2+M3+M4
baseline+M1+M2+M3+M4+M5
```

## 2. 推荐模块开关命名

| 模块 | 参数 | 默认值 | 说明 |
|---|---|---:|---|
| M1 H-VQG | `--view_quality_mode {none,raw,raw_clip,hvqg}` | `none` | 默认不启用质量门控，保证 baseline |
| M1 Raw Gate | `--raw_gate_mode {none,fft,fft_clip,full}` | `none` | 原始帧阶段，只使用 RGB 信息 |
| M1 Mask Gate | `--mask_gate_mode {none,basic,temporal}` | `none` | FSAM3 后检查 mask 可靠性 |
| M1 Geometry Gate | `--geo_gate_mode {none,registered,reproj,full}` | `none` | COLMAP/SfM 后检查几何可靠性 |
| M1 keep ratio | `--raw_gate_keep_ratio / --mask_gate_keep_ratio / --geo_gate_keep_ratio <float>` | `1.0` | 每层默认保留全部 |
| M2 Mask | `--mask_mode {none,preprocess,alpha}` | `none` | 默认不用 mask |
| M3 Mask loss | `--use_mask_loss` | `false` | 开启 mask consistency loss |
| M3 BG opacity | `--use_bg_opacity_loss` | `false` | 开启背景不透明度惩罚 |
| M3 weight | `--lambda_mask` | `0.0` | mask loss 权重 |
| M3 weight | `--lambda_bg` | `0.0` | background opacity loss 权重 |
| M4 Pruning | `--pruning_mode {none,opacity,brightness,mask,topology}` | `none` | 默认不剪枝 |
| M4 schedule | `--pruning_start_iter` | 按 baseline 默认 | 避免过早剪掉有效结构 |
| M5 Meshing | `--meshing_mode {standard,small_trunc,edge_aware,post_boundary}` | `standard` | 默认标准 TSDF |
| 实验名 | `--method_tag` | 自动生成 | 保存组合标识 |

## 3. 默认配置必须等价 baseline

默认命令必须满足：

```bash
python train.py --source_path <scene> --model_path <out>
```

等价于：

```bash
python train.py \
  --source_path <scene> \
  --model_path <out> \
  --view_quality_mode none \
  --raw_gate_mode none \
  --mask_gate_mode none \
  --geo_gate_mode none \
  --mask_mode none \
  --lambda_mask 0.0 \
  --lambda_bg 0.0 \
  --pruning_mode none \
  --meshing_mode standard
```

任何新增代码必须做到：

- 不传新参数时不改变旧训练结果。
- 不要求 baseline 提供 mask 文件。
- 不要求 baseline 路径包含新目录。
- 不要求 baseline 额外运行预处理。

## 4. 配置保存规则

每次训练必须保存：

```text
/data/fj/F2DMAS/00-论文优化重构/数据管理/06-实验输出/<sample>/<method_tag>/
├── config.yaml
├── command.txt
├── metrics.json
├── train.log
├── render_metrics.json
├── mesh_metrics.json
└── phenotype_metrics.json
```

`config.yaml` 至少记录：

- dataset/sample ID
- module switches
- loss weights
- pruning thresholds
- TSDF parameters
- random seed
- code commit hash 或代码版本标记
- 输入 mask 路径和 prompt ID

## 4.1 新版数据管理根目录

后续所有新版执行数据统一存放在：

```text
/data/fj/F2DMAS/00-论文优化重构/数据管理
```

该目录是后续训练、评测、论文统计的统一数据入口。旧目录仍作为原始证据保留，但新增实验、重跑结果、最终锁定数据和索引必须同步进入新版 `数据管理`。

目录命名规则：

```text
数据管理/
├── 00-规范与索引/
├── 01-输入图像/
├── 02-位姿COLMAP/
├── 03-分割Mask/
├── 04-重建结果/
├── 05-评测结果/
├── 06-实验输出/
└── 07-运行脚本与超参/
```

COLMAP 数据分层：

| 目录 | 含义 |
|---|---|
| `02-位姿COLMAP/01-current_ok/` | 旧 `04-COLMAP` 中当前可用结果 |
| `02-位姿COLMAP/02-rerun_original_candidates/` | 原图或 FFT 保留原图重跑出的候选结果 |
| `02-位姿COLMAP/03-final_locked/` | 最终确认用于训练和论文实验的位姿版本 |

新增规则：

- 不允许把新版实验输出散落在旧目录中作为唯一结果。
- 大体量历史资源可通过软链接集中到 `数据管理`，避免重复拷贝。
- 每次重跑完成后必须刷新 `00-规范与索引/dataset_index.csv`。
- 训练入口优先读取 `数据管理/02-位姿COLMAP/03-final_locked/`；未锁定前可读取 `02-rerun_original_candidates/` 做验证，但论文正式实验必须记录最终选用版本。
- `06-实验输出/<sample>/<method_tag>/` 是新版算法组合实验的默认输出位置。
- 每个阶段运行过的脚本、命令、超参和日志入口必须同步到 `07-运行脚本与超参/<stage>/{scripts,configs,docs,logs}/`。

## 5. 组合合法性规则

| 组合 | 是否允许 | 说明 |
|---|---|---|
| `baseline` | 允许 | 纯 2DGS 或当前标准路径 |
| `baseline+M1` | 允许 | 只改变输入帧集合 |
| `baseline+M2` | 允许 | preprocessing-only，不能加入 loss |
| `baseline+M3` | 条件允许 | 必须有 mask；若无 mask 应报清晰错误 |
| `baseline+M4` | 允许 | pruning 可独立测试 |
| `baseline+M5` | 允许 | meshing 可独立测试 |
| `baseline+M2+M3` | 允许 | mask 生成和 mask loss |
| `baseline+M2+M3+M4` | 允许 | mask loss + pruning |
| `baseline+M2+M3+M4+M5` | 允许 | full method |

## 6. 禁止事项

- 禁止在读取训练图像时默认套用 mask。
- 禁止在 loss 中默认加入 mask loss。
- 禁止把 pruning 写死为训练结束自动执行。
- 禁止让 edge-aware meshing 替代 standard TSDF 的默认路径。
- 禁止为了某个模块修改 baseline 数据格式。
- 禁止只用不同脚本代表不同方法，必须有统一入口和明确参数。

## 7. 模块开发验收

每个模块合入前必须提供：

- 单独开关测试：开和关都能跑。
- 至少一个组合测试：和另一个模块组合不冲突。
- baseline 回归测试：默认参数输出路径和指标字段不缺失。
- 配置记录测试：运行后能明确追溯本次组合。
