# 验收标准与风险清单

## 1. 方法层面验收

必须满足：

- 新论文不再像单纯 pipeline。
- 至少有一个明确 loss：`L_mask`、`L_bg-opacity`。
- 至少有一个明确 score：`S_i` pruning score。
- 至少有一个明确 weight/correction：`w'` edge-aware TSDF weight。
- 每个模块都有消融实验。
- 方法命名统一，不能让 F2DMAS、FSAM3、2DGS、TSDF 平行堆叠。

建议主方法名：

```text
Plant-aware 2DGS
```

子模块：

```text
Mask-constrained Gaussian Optimization
Topology-aware Gaussian Pruning
Edge-aware Thin-leaf Meshing
```

## 2. 工程层面验收

必须满足：

- 默认配置严格运行 baseline。
- 每个新增模块独立开关。
- 任意模块组合可通过同一入口运行。
- 运行结果保存 command/config/metrics/log。
- 新模块不强制依赖彼此，除非有清晰报错。

baseline 回归检查：

```text
python train.py --source_path <scene> --model_path <out>
```

必须不需要 mask、不执行 pruning、不改变 standard TSDF。

## 3. 实验层面验收

必须有：

- 主对比。
- 模块消融。
- pruning 消融。
- 表型误差。
- leaf boundary 专项分析。
- 至少一组失败案例或限制讨论。

优先补齐：

- background Gaussian ratio。
- floating artifact ratio。
- connected component count。
- leaf edge thickness。
- leaf width bias。

## 4. 图表层面验收

必须有：

- Fig. 1：问题和贡献。
- Fig. 3：核心方法。
- Fig. 5：剪枝。
- Fig. 7：叶片边界。
- Fig. 9：表型测量。
- Table 4：核心消融。
- Table 7：核心表型误差。

## 5. 写作层面验收

必须做到：

- 不再主打“数字孪生平台”。
- 主打“植物感知 2DGS 方法”。
- 不夸大真实田间泛化。
- 明确数据来自 smartphone-based potted plant acquisition。
- 把 leaf width bias 从缺点改造成方法动机和改进证据。

## 6. 主要风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| M3 mask loss 让边界收缩过度 | leaf width 被低估，PSNR 下降 | boundary ignore band、loss warm-up、lambda sweep |
| M4 pruning 剪掉真实叶片或叶柄 | 表型误差上升 | 保守阈值、top-K component、high view coverage 保留 |
| M5 修正过强 | mesh 变碎或叶宽低估 | 设置 max shrink，报告 connected components |
| prompt sensitivity 太强 | 方法稳定性被质疑 | prompt ensemble 或固定推荐 prompt |
| 缺少高精度 3D GT | 几何指标不足 | pseudo-GT、artifact ratio、leaf edge thickness、表型误差 |
| 现有样本 GT 较少 | 统计说服力不足 | 明确样本范围，增加可视化和 Bland-Altman |

## 7. Go/No-Go 决策

M3：

- Go：相比 preprocessing-only，背景 Gaussian 或 artifact 降低，渲染指标不明显下降。
- No-Go：PSNR/LPIPS 明显恶化且表型误差无改善。

M4：

- Go：Gaussian 数、mesh time、artifact ratio 下降，trait error 不升。
- No-Go：只减少 Gaussian 数但叶片结构受损。

M5：

- Go：leaf width bias/MAPE 下降，plant height/canopy width 不恶化。
- No-Go：边界看似更细但 mesh 碎片显著增加或 leaf width 低估严重。
